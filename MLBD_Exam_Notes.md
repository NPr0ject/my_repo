## Структура ноутбуков

| Файл | Задача | Модели |
|------|--------|--------|
| `regression.ipynb` | Регрессия | Ridge, Lasso, LinearRegression (МНК), DecisionTreeRegressor |
| `classification.ipynb` | Классификация | KNN, GaussianNB, DecisionTreeClassifier, LogisticRegression |

Оба ноутбука следуют одной и той же последовательности этапов, соответствующих заданию экзамена:

1. Загрузка данных
2. Предобработка (dropna, отбор числовых признаков)
3. EDA — гистограммы, scatter/boxplot, корреляционная матрица
4. Train/test split + масштабирование (StandardScaler)
5. Optuna — подбор гиперпараметров (кросс-валидация 5-fold)
6. Обучение финальных моделей, вычисление метрик
7. Визуализация сравнения моделей
8. Анализ лучшей модели (предсказания vs реальные, confusion matrix, feature importances)
9. Деплой — сохранение модели через joblib

## Описание алгоритмов

### Регрессия

**LinearRegression (МНК)** — метод наименьших квадратов. Находит коэффициенты, минимизирующие сумму квадратов остатков. Не имеет гиперпараметров, служит бейзлайном.

**Ridge (L2-регуляризация)** — добавляет к функции потерь штраф `α × Σβ²`. Штраф сжимает коэффициенты к нулю, но не обнуляет их полностью. Полезен при мультиколлинеарности: стабилизирует оценки, распределяя вес между коррелированными признаками. Гиперпараметр `alpha` (α) контролирует силу регуляризации — чем больше α, тем сильнее сжатие.

**Lasso (L1-регуляризация)** — добавляет штраф `α × Σ|β|`. В отличие от Ridge, способен обнулять коэффициенты, выполняя отбор признаков автоматически. При больших α модель оставляет только самые важные предикторы. Это делает Lasso особенно полезным, когда число признаков велико, а информативных среди них мало.

**DecisionTreeRegressor** — строит дерево решений, разбивая пространство признаков на области. В каждом листе предсказание — среднее значение таргета обучающих объектов в этом листе. Не требует масштабирования признаков. Гиперпараметры: `max_depth`, `min_samples_split`, `min_samples_leaf`.

### Классификация

**KNN (k-Nearest Neighbors)** — относит объект к классу, наиболее частому среди k ближайших соседей. Требует масштабирования (иначе признаки с большим диапазоном доминируют). Гиперпараметры: `n_neighbors` (k), `weights` (uniform/distance), `p` (метрика: 1 = Manhattan, 2 = Euclidean).

**Gaussian Naive Bayes** — вероятностный классификатор на основе теоремы Байеса с «наивным» предположением о независимости признаков. Предполагает гауссово распределение каждого признака. Быстрый, хорошо работает на высокоразмерных данных. Гиперпараметр: `var_smoothing` — добавляет дисперсию для численной стабильности.

**DecisionTreeClassifier** — аналогичен регрессионному дереву, но в листьях предсказывает класс (по большинству голосов). Гиперпараметры: `max_depth`, `min_samples_split`, `min_samples_leaf`, `criterion` (gini/entropy). Не требует масштабирования.

**LogisticRegression** — линейный классификатор, моделирующий вероятность класса через сигмоиду. Параметр `C` — обратная сила регуляризации (меньше C = сильнее регуляризация). `penalty` (l1/l2) выбирает тип штрафа. L1-штраф может обнулять коэффициенты (аналог отбора признаков). Требует масштабирования.

## Optuna — подбор гиперпараметров

Optuna — фреймворк автоматического подбора гиперпараметров. Использует TPE (Tree-structured Parzen Estimator) для эффективного поиска.

### Пространства поиска

**Регрессия:**

| Модель | Гиперпараметр | Диапазон |
|--------|---------------|----------|
| Ridge | `alpha` | [1e-3, 100], log |
| Lasso | `alpha` | [1e-4, 100], log |
| DecisionTree | `max_depth` | [2, 30] |
| DecisionTree | `min_samples_split` | [2, 20] |
| DecisionTree | `min_samples_leaf` | [1, 20] |

**Классификация:**

| Модель | Гиперпараметр | Диапазон |
|--------|---------------|----------|
| KNN | `n_neighbors` | [1, 50] |
| KNN | `weights` | {uniform, distance} |
| KNN | `p` | {1, 2} |
| NaiveBayes | `var_smoothing` | [1e-11, 1e-1], log |
| DecisionTree | `max_depth` | [2, 30] |
| DecisionTree | `min_samples_split` | [2, 20] |
| DecisionTree | `min_samples_leaf` | [1, 20] |
| DecisionTree | `criterion` | {gini, entropy} |
| LogisticRegression | `C` | [1e-3, 100], log |
| LogisticRegression | `penalty` | {l1, l2} |

### Как изменить количество итераций

В ноутбуке переменная `N_TRIALS = 50`. Увеличь до 100–200 для более тщательного поиска (но дольше работает).

## Метрики

### Регрессия

| Метрика | Описание |
|---------|----------|
| **RMSE** | Root Mean Squared Error — корень из средней квадратичной ошибки. Чувствительна к выбросам. Измеряется в единицах таргета. |
| **MAE** | Mean Absolute Error — средняя абсолютная ошибка. Менее чувствительна к выбросам, чем RMSE. |
| **R²** | Коэффициент детерминации. R² = 1 — идеальное предсказание; R² = 0 — модель не лучше среднего; R² < 0 — модель хуже константного предсказания. |

### Классификация

| Метрика | Описание |
|---------|----------|
| **Accuracy** | Доля правильных предсказаний. Хороша при сбалансированных классах. |
| **Precision** | Доля истинных положительных среди всех предсказанных положительных (взвешенная по классам). |
| **Recall** | Доля истинных положительных среди всех фактических положительных (взвешенная по классам). |
| **F1** | Гармоническое среднее Precision и Recall. Учитывает и ложные положительные, и ложные отрицательные. |

> Все метрики классификации в ноутбуке используют `average='weighted'` для учёта дисбаланса классов.

## Приложения

### Приложение А. Масштабирование

StandardScaler преобразует каждый признак: `z = (x - μ) / σ`, где μ — среднее, σ — стандартное отклонение. Это необходимо для:

- **Ridge / Lasso / LinearRegression** — регуляризация штрафует большие коэффициенты; без масштабирования признаки с большим диапазоном получают несправедливый штраф.
- **KNN** — расстояния вычисляются по всем признакам; без масштабирования признаки с большим диапазоном доминируют.
- **LogisticRegression** — градиентный спуск сходится быстрее на масштабированных данных.

**Decision Tree не требует масштабирования**, так как работает с пороговыми разбиениями, а не с расстояниями или коэффициентами.

### Приложение Б. Линейные модели: Ridge vs Lasso vs МНК

| Свойство | МНК | Ridge | Lasso |
|----------|-----|-------|-------|
| Регуляризация | Нет | L2 (Σβ²) | L1 (Σ\|β\|) |
| Обнуляет коэффициенты | Нет | Нет | Да |
| Устойчив к мультиколлинеарности | Нет | Да | Частично |
| Отбор признаков | Нет | Нет | Да |
| Гиперпараметр | — | alpha | alpha |

Ridge и Lasso — это расширения МНК с регуляризацией. При `alpha → 0` обе модели стремятся к обычному МНК.

### Приложение В. Кросс-валидация

В ноутбуках используется 5-fold кросс-валидация (cv=5). Данные разбиваются на 5 частей; модель обучается 5 раз, каждый раз на 4 частях и валидируется на оставшейся. Средняя метрика по 5 фолдам — устойчивая оценка качества.

Optuna максимизирует средний CV-скор:
- Регрессия: `neg_mean_squared_error` (maximize = minimize MSE)
- Классификация: `accuracy`

### Приложение Г. Деплой модели

Лучшая модель сохраняется через `joblib.dump()`. Для загрузки:

```python
import joblib

model = joblib.load('best_regression_model.pkl')
# или
model = joblib.load('best_classification_model.pkl')

# Для моделей, требующих масштабирования:
scaler = joblib.load('regression_scaler.pkl')
X_new_scaled = scaler.transform(X_new)
pred = model.predict(X_new_scaled)

# Для классификации — декодирование меток:
le = joblib.load('classification_label_encoder.pkl')
pred_labels = le.inverse_transform(pred)
```

### Приложение Д. Советы по адаптации

1. **Категориальные признаки** — ноутбуки оставляют только числовые столбцы. Если нужно включить категориальные, используй `pd.get_dummies()` или `OneHotEncoder` перед шагом масштабирования.

2. **Пропуски** — используется простой `dropna()`. Для более аккуратной обработки можно заменить на `SimpleImputer` (среднее, медиана, мода).

3. **Выбросы** — добавь ячейку с удалением/клиппингом выбросов перед обучением, если EDA показывает их наличие.

4. **Feature engineering** — можно добавить новые признаки (полиномиальные, взаимодействия) между шагами 3 и 4.

5. **Мультикласс** — все классификаторы поддерживают мультикласс из коробки. Метрики используют `average='weighted'`.

6. **Увеличение N_TRIALS** — для лучшего подбора гиперпараметров увеличь до 100–200, но учти, что время выполнения растёт линейно.
